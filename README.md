# Guitar Notation Generator

Local-first Python application for validating guitar music and producing a readable lead sheet, tablature, chord diagrams, and a practice-band MIDI arrangement. The command line and repository's Copilot agent skill use the same package.

## Current version and capabilities

Current application version: **0.2.0**.

- Validate song and lesson-plan JSON, including pitches, guitar voicings, melody/tab agreement, chord spelling, and bar lengths.
- Render agent-friendly Markdown and LilyPond source containing melody, chord, and tablature staves plus timed chord diagrams.
- Generate a seven-track Type 1 MIDI arrangement: melody guide, guitar, keys, bass, horns, strings, and drums.
- Compile a PDF when LilyPond 2.24 or later is installed.

The musical input is intentionally event-based. It does not model every possible engraving or performance detail; review the generated score and MIDI before using them as final teaching or publication material.

## Requirements

- Python 3.10 or later
- LilyPond 2.24 or later for PDF output

## Install

```bash
git clone <your-repository-url>
cd guitar-notation-generator
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
```

The core CLI has no third-party Python runtime dependencies. Install LilyPond separately from [lilypond.org](https://lilypond.org/download.html).

## Use the command line

Check the included example:

```bash
guitar-notation check references/example.json
```

Render it:

```bash
guitar-notation render references/example.json --out output --name score
```

This writes `score.md`, `score.ly`, and `score_full_band.mid`; if LilyPond is installed, it also writes `score.pdf`. To skip MIDI or PDF generation, use `--no-midi` or `--no-pdf`.

Without installing the package, run from the repository root with:

```bash
PYTHONPATH=src python -m guitar_notation.cli check references/example.json
PYTHONPATH=src python -m guitar_notation.cli render references/example.json --out output
```

`render` validates first and stops on errors. `--force` permits rendering despite validation errors. Before writing, the renderer removes existing `.md`, `.ly`, `.pdf`, and `.mid` files in the selected output directory; choose a dedicated output directory for each project.

## Input format

The canonical format is documented in [`references/schema.json`](references/schema.json). The Python validator adds musical checks beyond the JSON Schema; the two are maintained together. A complete song and a lesson-plan exercise are provided in [`references/example.json`](references/example.json) and [`references/example_lesson_plan.json`](references/example_lesson_plan.json).

Conventions:

- Pitch names use sounding scientific pitch (C4 is middle C); default tuning is `E2 A2 D3 G3 B3 E4`, low to high.
- Tablature strings are numbered 1 (high e) to 6 (low E). Chord voicings list the six strings low E to high e; `-1` means muted and `0` means open.
- Each bar has an `events` array. Event durations are whole-note denominators `1`, `2`, `4`, `8`, or `16`, optionally dotted (for example, `"4."`). Durations in a bar must exactly fill its meter.
- `play_chord: true` plays the full chord voicing on the guitar track. An optional `melody` on that event is an independent guide line and can differ from the voicing's highest note; omit `tab`, since the chord voicing supplies it.
- Optional bar-level `section` labels organize lesson sections in the Markdown output.

Supported meters use denominators 1, 2, 4, 8, or 16. The MIDI arranger adapts to common meters including 3/4, 4/4, 5/4, 6/8, 9/8, and 12/8, though its accompaniment is heuristic.

The repository includes [`.github/skills/guitar-notation/SKILL.md`](.github/skills/guitar-notation/SKILL.md). It instructs a compatible agent to produce JSON, validate it, correct errors, then render the PDF and MIDI. ## Known limitations

- MIDI backing parts are generated by a style and meter heuristic. Lo-fi/60s cues select a warm Rhodes keys track and Mellotron flute guide; the three presets are fixed rather than arbitrary instrument programming. They are practice accompaniment, not a carefully voiced arrangement or a substitute for a human performer.
- Events provide a single duration and simultaneous pitch collections. Fine-grained rhythms, ties, tuplets, pickups, articulations, and independent rhythmic alignment among voices are not modeled.
- Validation checks chord-name/voicing pitch classes and slash bass, but cannot determine musical intent, ergonomic fingering, voice-leading quality, or every possible chord spelling.
- The schema describes structural constraints; the Python validator remains authoritative for additional musical checks.
- There is no web UI or HTTP API; use the CLI directly or through the Copilot agent skill.
